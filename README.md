# AITU Task Hub Bot

The repository now also contains the first Android migration layer: a FastAPI
backend that reuses the bot's existing database and task business logic.

## TaskHub API (Android migration)

Run the API locally:

```bash
pip install -r requirements.txt
uvicorn backend.main:app --reload
```

Interactive API documentation is available at `http://127.0.0.1:8000/docs`.
The first vertical slice exposes task CRUD under
`/api/v1/users/{user_id}/tasks`; the Telegram bot continues to work as before.

For this migration stage, `user_id` is passed in the URL to preserve the
existing Telegram data model. It must be replaced by authenticated user data
before a public deployment.

Telegram-бот для университетского расписания и дедлайнов. Стек: Python, aiogram 3, SQLAlchemy 2, async SQLite (`aiosqlite`), APScheduler.

## Функции

- Расписание: создание, просмотр по дням и неделям, редактирование и удаление пар; предмет, аудитория, преподаватель, тип занятия и чётность недели.
- Проверка пересечений: пары одного пользователя в один день не могут пересекаться, если их недели совпадают. Числитель и знаменатель допускают одинаковое время; соседние интервалы без пересечения разрешены.
- Дедлайны: задачи с предметом, необязательным сроком и обычным/высоким приоритетом; выполнение, возобновление, редактирование, удаление и фильтры статуса.
- Дашборд: текущая и следующая пара, количество пар сегодня, просроченные задачи, ближайшие сроки и задачи без срока. Горизонт — 1, 3, 7 или 14 календарных дней, включая сегодня.
- Настройки: язык интерфейса ru/en/kk, IANA-часовой пояс, уведомления, напоминание за 0/5/10/15/30/60 минут, смещение чётности недели.
- Напоминания о начале пар с учётом местной даты и чётности. Значение 0 означает напоминание в момент начала, а не отключение.
- Доступ к задачам и парам ограничен владельцем; handlers проверяют актуальность кнопок и экранов.
- Переводятся шаблоны интерфейса, но не пользовательские названия предметов, тексты задач, аудитории и имена преподавателей. При выводе HTML пользовательский текст экранируется.

Команды реализованных разделов: `/start`, `/schedule`, `/tasks`, `/add`, `/settings`, `/dashboard`. Доступность разделов в запущенном боте зависит от регистрации соответствующих routers в `main.py`.

## Требования и запуск

Нужен **Python 3.10+** и доступная база часовых поясов IANA. На системах без системной базы зон можно установить пакет `tzdata`.

Из корня проекта:

```sh
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
```

Получите токен у BotFather. Передайте его через переменную окружения `BOT_TOKEN`; не сохраняйте настоящий токен в коде или репозитории. Например, в POSIX-shell можно ввести его без помещения значения в историю команд:

```sh
read -r BOT_TOKEN
export BOT_TOKEN
venv/bin/python main.py
```

После `read` введите токен и нажмите Enter (обычный `read` не скрывает ввод на экране). Альтернатива — локальный файл `.env` с переменной `BOT_TOKEN`, загружаемый `python-dotenv`; убедитесь, что он исключён из Git. Без токена конфигурация выдаёт ошибку.

`main.py` запускает реального бота: обращается к Telegram, запускает планировщик и создаёт/обновляет SQLite. Файл `db.sqlite3` расположен относительно **текущей рабочей директории**, поэтому запускайте из корня проекта. Для тестов запуск `main.py` не нужен.

## Время и чётность

- Время пар — местное время пользователя. Новые пары должны начинаться и заканчиваться в один день, причём конец строго позже начала. Переходящие через полночь старые записи поддерживаются отображением дашборда, но не новым вводом.
- Дедлайн хранится как **local naive datetime**: дата и часы без `tzinfo`, интерпретируемые в выбранной зоне пользователя, **не UTC**. Смена зоны не пересчитывает сохранённые часы пар и задач. Например, дедлайн `12:00` останется `12:00` после смены зоны, хотя соответствующий момент UTC изменится.
- На дашборде срок строго раньше текущего местного времени считается просроченным. Верхняя граница горизонта — полночь после последнего включённого дня, не включительно. Выполненные задачи исключены; просроченные показаны независимо от горизонта.
- Недели считаются по **ISO 8601**: с понедельника; неделя №1 содержит 4 января. При смещении 0 нечётная ISO-неделя — числитель (`numerator`), чётная — знаменатель (`denominator`). Смещение 1 меняет их местами. `all` означает каждую неделю.
- На границе года используется именно номер ISO-недели: 1 января может относиться к неделе предыдущего ISO-года. Это не непрерывное чередование от даты начала семестра.
- Напоминание проверяет местную дату **начала пары**, включая переход через полночь при добавлении интервала напоминания.

## База данных и миграция

`database/models.py:async_main()` создаёт отсутствующие таблицы и добавляет отсутствующие настройки в старую таблицу `users`: `language`, `notifications_enabled`, `reminder_minutes`, `week_parity_offset`, `dashboard_days`. Значения по умолчанию: `en` (английский), включено, 15 минут, смещение 0, горизонт 7 дней. Сохранённый выбор языка существующих пользователей не изменяется; русский и казахский доступны в настройках. Миграция аддитивная и повторяемая; существующие пользователи, расписание и задачи должны сохраняться. Это не универсальная миграция произвольных старых схем.

**Перед обновлением сделайте резервную копию.** Остановите бот и другие процессы записи. Например, при установленном SQLite CLI (имя копии должно быть новым):

```sh
sqlite3 db.sqlite3 ".backup 'db.before-migration.sqlite3'"
```

Проверьте копию и храните её отдельно от рабочей БД. SQLite backup корректнее простого копирования одного файла при возможном WAL. Для восстановления сначала остановите все подключения и сохраните текущую БД вместе с сопутствующими файлами; не заменяйте открытую базу. Миграцию сначала проверяйте на отдельной копии, не на единственном экземпляре данных.

## Тесты

Дополнительный тестовый фреймворк не нужен: используется стандартный `unittest`, включая `IsolatedAsyncioTestCase`. Зависимости приложения должны быть установлены.

```sh
venv/bin/python -m unittest discover -s tests -v
```

Набор не требует `BOT_TOKEN`, не импортирует `main.py`, не запускает live bot и не подключается к рабочему `db.sqlite3`:

- `tests/test_database.py` — реальные async SQLite in-memory CRUD, сортировка/фильтры, ownership, rollback после невалидного изменения, конфликты и чётность, настройки и выборка уведомлений. Подменяются `db_requests.async_session`, `models.async_session` и `models.engine`; соединения освобождаются после теста. Миграция тестируется на отдельной старой схеме с существующими данными и с `patch(models.engine)`, включая повторные запуски.
- `tests/test_calendar_dashboard.py` — локальная полночь, ISO-чётность на границе года, смещение, local naive сроки и границы горизонта, старые ночные пары, ru/en/kk, неизменность пользовательского текста и HTML-экранирование.
- `tests/test_handlers.py` — guards экранов, сохранение черновика при обновлении dashboard, выбор языка, ручной ввод зоны, невалидное время и дата. Telegram и внешние эффекты подменены mocks.
- `tests/test_notifications.py` — фиксированное время, переход через полночь, чётность, нулевой интервал, локализация по получателю, HTML, ошибки отправки и конфигурация scheduler. Отправка сообщений и запуск scheduler замоканы.

Тесты проверяют требуемое поведение без `expectedFailure`: незавершённые изменения production-кода остаются видимыми ошибками, а не скрываются как успешные проверки.

### Обнаруженные ограничения снимка при первом прогоне

При параллельной доработке интеграции локализации первый прогон из 38 тестов выявил:

- `update_user(language=...)` отклоняет ru/en/kk как неизвестную настройку (3 ошибки subtests).
- Scheduler отправляет русский шаблон получателям en/kk (2 падения subtests).

При чтении также обнаружено, что `main.py` ещё подключал только start/schedule/add routers, а `/start` использовал прежнее русское меню. Эти части дорабатываются отдельно; тесты выше не являются end-to-end проверкой регистрации routers или live Telegram. После завершения интеграции повторите прогон. На Python 3.14 также наблюдается `DeprecationWarning` из-за `datetime.utcnow` в модели пользователя.
